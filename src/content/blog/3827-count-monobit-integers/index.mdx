An integer is monobit if its binary representation consists of only 0s or only 1s.

Given an integer n, return the count of monobit integers in the range [0, n].

- Examples
- Constraints
- [Approach 1: Brute Force Enumeration](#approach-1-brute-force-enumeration)
- [Approach 2: Mathematical Bit Length](#approach-2-mathematical-bit-length)
- [Approach 3: Iterative Bit Generation](#approach-3-iterative-bit-generation)

## Examples

### Example 1

**Input:**
```text
n = 1
```

**Output:**
```text
2
```

**Explanation:**
The integers in the range [0, 1] have binary representations "0" and "1".

Each representation consists of identical bits. Thus, the answer is 2.

### Example 2

**Input:**
```text
n = 4
```

**Output:**
```text
3
```

**Explanation:**
The integers in the range [0, 4] include binaries "0", "1", "10", "11", and "100".

Only 0, 1 and 3 satisfy the Monobit condition. Thus, the answer is 3.

## Constraints

```text
- 0 <= n <= 1000
```

## Approach 1: Brute Force Enumeration

**Intuition**
Iterate through every number from 0 to n and check if its binary representation contains only 0s or only 1s.

**Steps**
- Initialize a counter to 0.
- Loop through each integer i from 0 to n.
- For each i, check if it is 0 (all 0s) or if i & (i + 1) == 0 (all 1s).
- If the condition is met, increment the counter.
- Return the counter.

## Approach 2: Mathematical Bit Length

**Intuition**
A monobit integer is either 0 or a number of the form 2ᵏ - 1 (e.g., 1, 3, 7, 15...). The count of such numbers up to n is equivalent to the number of bits required to represent n + 1.

**Steps**
- Calculate n + 1.
- Return the bit length of n + 1. In most languages, this is a built-in operation or can be derived from the binary string length.

## Approach 3: Iterative Bit Generation

**Intuition**
Generate all numbers of the form 2ᵏ - 1 that are less than or equal to n, and count them along with 0.

**Steps**
- Initialize count = 1 (for 0) and val = 1.
- While val - 1 &lt;= n, increment count and multiply val by 2.
- Return count.
